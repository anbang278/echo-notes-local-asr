# 测试、交付与发布

本文件是本项目已确认的工程约束；尚无应用源码，不能从规范推断功能已实现。

## Pre-Development Checklist

读取 [项目规则](../../../AGENTS.md)、[研发交付约定](../../../docs/DEVELOPMENT.md) 和当前任务，核实相关源码、授权与未验证项。

## 约束

- 初始化检查入口为 `bash scripts/check.sh`，只覆盖文档、发布脚本模拟、公开清单与 Trellis；不是应用功能验收。
- 每份应用证据绑定任务、源码提交、版本、依赖与模型 revision、设备、音频许可／哈希、命令、预期、实际与限制。
- 按静态检查、mock、真实模型、干净 Mac、签名公证分层记录。未执行就标未验证；无证书的开发实验不能标为可分发应用。
- Pi 在持久功能分支保存提交并完成隔离测试交付；人工批准绑定当前交付。源码、依赖或包改变后旧批准失效。
- 测试安装与正式应用、模型和旧 Echo Notes 服务隔离。包、安装产物与源码哈希一致后，才请人工启动验收。
- 公共测试版需要可复现构建、组件许可、签名公证、真实下载首启、升级／回退与离线证据。初始化 CI 不生成假安装包或 Release。
- 正常任务不得自动提交会话记录或推送。初始化工件的首提交及公开推送是本次用户明确授权例外。

## Quality Check

逐项核对当前改动及任务测试证据；同步任务、README 与相关设计，缺证据项明确保留为未验证。
