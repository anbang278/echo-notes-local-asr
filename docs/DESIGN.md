# 设计理念与产品边界

状态：初始设计，待研发验证。更新时间：2026-10-16。

## 1. 为什么单独建设

Echo Notes 已有本地转写链路，但“作者自己的电脑可以运行”与“普通用户可以独立安装使用”之间，还隔着解释器、依赖、模型缓存、音频解码、启动配置、资源管理和故障处理。

本项目不是重新训练一个 ASR 模型，也不是制作一个通用模型商店。它要把本地转写变成可交付的产品能力：**用户选择在本机处理音频，系统负责把必要环境准备好，并持续保持可用。**

本地方案的价值首先是数据控制、无网络时可用以及不依赖转写服务商账户，而不仅是省下按量调用费。模型下载、计算资源、磁盘、电量与维护仍然有成本，产品应明示而非隐藏。

## 2. 用户与主要场景

首要用户是已经使用 Echo Notes 的 Mac 用户，希望转写会议、学习录音或语音笔记，但不愿学习 Python、命令行和服务部署。

最重要的三个场景是：首次安装后顺利完成第一次转写；日常使用时不用手动启动模型或复制接口地址；出现下载、内存或服务故障时，知道发生了什么以及如何恢复。

独立应用提供最小测试入口，便于区分“本机模型未就绪”与“插件连接异常”，不在首期另做一套笔记管理系统或录音编辑器。

## 3. 七条设计原则

### 3.1 用户配置的是能力，而非运行环境

默认提供一个经过验证的推荐模型。主界面表达“已安装、需要下载、正在准备、可用、需要处理”，不把 pip、虚拟环境和端口列表当作主要交互。

模型标识、服务地址、组件版本放在高级信息区，便于技术用户排查，而不是要求每个用户都填写。

### 3.2 一次明确授权，后续按已选策略运行

首次安装、模型下载、启用连接和升级由用户明确触发。用户启用“需要转写时自动启动”后，正常任务无需反复确认；开机启动默认关闭，不能因为安装应用就常驻加载模型。

“自动”不等于静默安装未知代码、自动使用付费云服务，或在用户停止后偷偷重启。

### 3.3 Mac 体验优先，不提前承担多平台成本

首期只承诺经过测试的 Apple Silicon Mac。Intel Mac、Windows、Linux 和移动端不进入首期验收范围。架构保留推理引擎适配接口，但不提前实现跨平台安装器或多引擎调度。

M2 / 16GB 是首轮验证设备，不是已验证的最低配置。8GB、M1、其他 macOS 版本都需要单独测试；设备属于 M 系列不能直接推出该软件版本一定兼容。

### 3.4 默认本地，数据边界可解释

下载运行程序和模型需要联网，但不携带用户录音。转写阶段仅在本机完成；失败时保留错误，不自动切换云端。后续文字分析和 Memory 是否联网，由 Echo Notes 对应功能独立说明和控制。

日志默认只保留必要状态，不保留录音、正文、令牌和完整个人路径。用户主动导出诊断包时仍需预览内容，不自动上传。

### 3.5 稳定性先于模型数量

先把 0.6B 普通转写的安装、长录音、取消和资源释放做完整，再加入 1.7B、说话人分离、时间对齐。既有实现可作为后续参考，不意味着这些能力要一并对外开放。

一个可被普通用户独立安装并稳定使用的模型，比一组只能在开发机上运行的模型更有价值。

### 3.6 故障和维护是主流程的一部分

下载要能暂停或恢复；模型损坏要能够定位并重下必要文件；服务未启动、模型未加载、正在推理应有不同状态。升级失败保留上一个可用版本；卸载运行程序、删除模型、删除临时数据是不同操作。

多个 Vault 共享同一套运行时与模型，不重复下载。关闭一个 Vault 不能停止另一个 Vault 正在使用的推理任务。

### 3.7 产品承诺以证据为准

“服务声明接受 8 小时音频”不等于“8 小时真实会议已经验收”。“分段恢复上传”不等于“推理进程崩溃后从上一个词继续”。文档、界面和发布说明必须严格区分协议能力、工程测试与实测表现。

## 4. 产品与仓库分工

| 责任 | Echo Notes 插件 | Local ASR 应用 |
|---|---|---|
| 录音、源笔记、Markdown 回写 | 主责 | 不读取整个 Vault，不直接改笔记 |
| 任务入口与文档关联 | 主责 | 通过协议返回任务状态和结果 |
| 本机软件安装与升级 | 仅指引独立安装 | 主责；用户批准后执行 |
| 模型下载、校验、删除 | 展示状态或打开助手 | 主责 |
| 本机进程、空闲卸载、资源状态 | 读取状态／按已授权策略请求 | 主责 |
| ASR 推理 | 发送任务 | 主责 |
| AI 分析、校对、Memory | 原有独立链路 | 首期不实现 |

Obsidian 官方社区目录政策明确禁止插件自行安装或更新自身及其依赖。因此首期把软件与模型安装动作放在独立应用中，而非在插件中执行安装脚本。独立应用方案不自动等于已通过插件审核；连接、启动等具体实现仍需按发布时政策核验。[S4](SOURCES.md#s4-obsidian-社区目录政策)

## 5. 目标使用流程

### 首次使用

用户在插件选择“本地转写”，未发现助手时看到独立安装入口；安装并首次打开应用后，完成设备检查，展示推荐模型、准确下载大小、下载来源与所需空间。用户点击下载后，由应用下载、校验、加载模型，再运行内置且许可清晰的短测试音频。

测试成功后，用户允许 Echo Notes 配对。插件获取已验证的服务地址、模型和本地访问凭据，经用户选择“使用本地转写”后保存设置。旧云端设置保留，不能覆盖其他服务商配置、AI 分析或 Memory 配置。

### 日常使用

用户按原来的方式录音并发起转写。应用在已授权的启动策略下准备模型，任务中心展示准备、上传、解码、推理和回写状态。结果保存成功后，才确认服务端清理。空闲时按设置释放模型内存。

### 异常与退出

下载中断时只恢复相同版本、相同文件的下载；端口被其他软件占用时不杀进程；更新时不截断正在执行的任务；内存不足时给出关闭其他应用或重试的建议，不静默换模型导致质量变化。

退出窗口不必等于退出服务，界面要说明；“退出并停止服务”必须处理活动任务。用户明确停止之后，不能被健康检查立即拉起。

## 6. 首期与后续边界

首期交付设备检测、独立安装、0.6B 模型管理、本地转写、任务状态、取消、连接恢复、配对配置、资源释放和可用诊断。主要中文界面，测试包含中文、中英混合及英文。

暂不做实时麦克风监听、声纹身份识别、多模型融合、云端账户体系、跨设备同步、局域网服务、远程管理，以及多模型同时驻留内存。说话人分离和时间对齐属于后续可选能力，不能强迫所有用户下载对应模型。

## 7. 怎样判断产品成功

首期不编造用户量、成功率或速度承诺。先用明确可验证的标准：普通用户在干净 Mac 上不用终端完成首次转写；断网后同样可以完成；失败有可理解的原因与恢复入口；插件既有笔记和云端设置不受影响。

小规模试用后再测首次安装成功率、首次可用所需步骤、下载重试恢复率、转写成功率和问题定位成本。性能统一记录冷启动、热启动、实时因子 RTF、峰值资源及失败样本，不使用作者单机一次跑通代替支持矩阵。
