# 技术架构与集成契约

> 本文协议和安全机制为设计约定；本轮仓库初始化未新增服务 API 或迁入应用实现，兼容性与鉴权均需后续任务实测。

状态：设计约束，不是已实现接口说明。更新时间：2026-10-16。

## 1. 推荐结构

```text
Echo Notes 插件
  录音 / 任务中心 / Markdown / Memory
       │ 本机鉴权 HTTP：能力、任务、结果
       ▼
Local ASR 服务进程（不扫描 Vault）
  任务协议 → 有界音频解码 → 单工作进程 → Qwen3-ASR
       ▲
       │ 用户级本地控制通道（Unix socket / 显式进程句柄）
       │
Mac 原生控制台／菜单栏应用
  首次引导 / 模型安装 / 服务启停 / 连接配对 / 诊断
       │
       ├─ 经过验证的只读运行时：Python + MLX + 推理代码 + 解码组件
       └─ 用户数据目录：模型 / 下载临时文件 / 任务结果 / 日志
```

进程控制和安装管理不开放为无鉴权的通用 HTTP 接口。应用无需管理员权限运行；不改变系统 Python、Homebrew 或全局 PATH。

## 2. 技术选型与决策门槛

| 层级 | 首选方案 | 原因与边界 |
|---|---|---|
| Mac 界面 | Swift + AppKit，优先复用既有控制台 | 避免为一个轻量助手再次分发 Electron；SwiftUI 可局部采用，不作为重写理由 |
| 推理层 | 独立 Python + MLX-Audio 进程 | 已有代码基础；MLX-Audio 有 Qwen3-ASR 支持 [S2](SOURCES.md#s2-mlx-audio) |
| 模型 | Qwen3-ASR-0.6B-8bit | 保留现有模型和已锁定 revision 作为基线，重新建立实测证据 |
| 解码 | 可再分发的固定构建 FFmpeg 或验证过的系统解码适配器 | 不再依赖固定 Homebrew 路径；选定的构建与许可需留证据 [S6](SOURCES.md#s6-ffmpeg-分发条件) |
| 发布 | 自包含、可签名的运行时与 `.app`，以 DMG 分发 | 终端用户不需要安装 Python、编译工具、uv 或 Homebrew |
| 存储 | 用户级 Application Support / Caches / Logs | 与 Vault 和应用二进制分离；多 Vault 共用 |

关键技术验证是：Python 运行时、原生扩展、MLX 动态库与解码组件在签名应用中的可移植性、加载路径、权限及资源释放。不能仅把开发机 `.venv` 打成压缩包就视为可分发。

M0 默认验证复用路线。若自包含 Python 打包产生不可接受的发布或维护成本，再做受限的 Swift 原生推理对照验证。上游已有 Swift Qwen3-ASR 实现，但替换引擎仍需重新验证长音频、结果质量、任务协议及取消行为，不能按“无 Python”直接认定更成熟。[S7](SOURCES.md#s7-可选-swift-推理实现)

## 3. 程序、运行时与模型分离

应用二进制和解释器由发布流水线构建、锁定、签名，正常运行期间不执行 `pip install`，也不直接从上游 `main` 下载 Python 代码执行。首次启动只下载经过批准的模型数据文件；禁止模型加载器隐式联网补齐未申明资源，禁止动态执行模型仓库代码。

运行时放在签名应用包内的方案优先验证。任何独立可执行组件更新都必须作为经校验的版本化软件升级处理，不与普通模型数据下载混为一谈。

建议数据目录（设计示例，不保证已存在）：

```text
~/Library/Application Support/Echo Notes Local ASR/
  config.json
  models/<model-key>/<revision>/
  jobs/<job-id>/
  pairing/                   # 仅非敏感的配对元数据
~/Library/Caches/Echo Notes Local ASR/
  downloads/*.partial
~/Library/Logs/Echo Notes Local ASR/
  service.log
```

令牌由应用安全存储与插件 SecretStorage 分别保管，不把令牌写进 `config.json`、连接描述文件、Vault、URL 或日志。SecretStorage 的主机实现不假设等同 macOS Keychain。

旧 Hugging Face 缓存可由用户主动选择复用。必须先校验；默认不修改或删除共享缓存。迁移时不得自动删除旧服务、旧缓存或旧控制台。

## 4. 模型管理

模型清单至少包括 model ID、revision、文件路径白名单、逐文件字节数与 SHA-256、下载来源、许可证入口、引擎兼容版本、能力声明和实测硬件范围。可信来源由应用内置清单或签名清单建立；不能只校验一个同样来自不可信位置的 checksum 文件。

下载写入独立临时目录。支持续传时必须验证同一 revision 和远端文件身份；收到完整响应、ETag 改变或校验失败时按明确规则重下，不能错误拼接。完成逐文件校验后原子标记为已安装，再进行真实模型加载测试。

安装空间估算同时考虑下载临时文件、模型最终文件、替换备份与音频任务临时空间；数字必须来自实际产物清单。安装目录存在、模型文件校验通过、模型加载成功是三个不同状态。

普通转写不加载或强制下载说话人分离、对齐模型。模型安装／删除对同一目标加锁，活动任务正在使用的模型不能删除。

## 5. 本机 API 与兼容策略

保留标准 `POST /v1/audio/transcriptions` 和 `GET /v1/models` 兼容入口；Echo Notes 优先使用已有本地任务协议，以便上传、取消与结果恢复。

| 路径 | 目标职责 |
|---|---|
| `/health` | 最小运行状态；未配对不泄露任务和个人路径 |
| `/v1/models` | 已安装且实际可用的转写模型；不混入尚未下载项 |
| `/v1/local-asr/capabilities` | 服务身份、协议版本、实例 ID、兼容能力 |
| `/v1/local-asr/jobs` | 创建带幂等请求 ID 的任务 |
| `/v1/local-asr/jobs/{id}/audio` | 有界分块上传和校验 |
| `/v1/local-asr/jobs/{id}/commit` | 提交计算，重复提交不能重复推理 |
| `/v1/local-asr/jobs/{id}` | 状态及取消；只有所属客户端可以访问 |
| `/v1/local-asr/jobs/{id}/result` | 获取成功结果；插件落盘后再确认清理 |

既有协议基线为 v1，服务标识为 `echonotes-mlx-asr`。首轮不得随意更名破坏旧客户端。能力字段只能做向后兼容扩展；引入不兼容身份、鉴权或任务语义时，应明确客户端版本要求或使用新协议版本。

现有插件只对 18080/18081 端口识别专有任务协议。新服务先在隔离端口测试，不挤占旧实例；正式实现动态端口发现时需要同时修改插件的发现和协议判断，不能只改服务端端口。保留 loopback 地址与重定向防护，不为便利扩成远程 URL。

### 鉴权、发现与配对

只监听 `127.0.0.1`；保留 Host/Origin 校验，并增加客户端令牌及任务所有权检查。回环地址不等于任何本机进程均可信；本机制不承诺抵御已控制同一用户账户的恶意程序。

自动发现只提供地址与不敏感的实例信息，不能把“该端口返回预期 service 字符串”当成可信身份认证。首次连接由用户在本地应用确认，使用单次、短期、不可重放的配对挑战交换长期令牌；最终机制在 M1 做威胁评审。令牌不通过命令行参数和 URL 传递。

现有插件的可选 API Key 字段可作为过渡手动配对入口，但新服务不能为兼容旧版而无提示关闭鉴权。自动配置属于后续主插件集成，不能绕过插件直接改写 `data.json` 或密钥存储。

## 6. 进程与任务生命周期

应用管理轻量服务进程，重模型按授权策略加载。一个计算槽串行推理，上传缓存有明确限额；不因为多个 Vault 发起请求就各自加载一份模型。

任务与 UI 连接解耦。插件热重载后可通过已保存的任务 ID 恢复同一服务实例的连接；应用退出或崩溃后的未完成推理，首期可以明确标记失败，并提供重新发起入口，不承诺断点续算。

取消先进入 `canceling`。只有实际停止计算后才返回 `canceled`；超时需要终止时，只操作经过身份核验且由本应用创建的工作进程。UI 不得把关闭 HTTP 连接当作后端已停止。活动任务期间禁止静默升级、卸载或空闲回收。

服务重启需更换实例 ID；旧任务恢复必须检测实例变化。结果清理遵守“先成功保存，后确认删除”；TTL 清理需在界面和错误信息中说明恢复期限。不要把当前协议的 1GiB / 8h 配额当作已完成的公开容量承诺。

## 7. 音频与结果正确性

沿用有界读盘、分窗解码和结果组合，避免把完整长录音扩展成内存中的大 PCM。拒绝空文件、损坏文件、异常采样、越界大小与无法识别的容器，超限不能静默截断。

结果至少包含文本、模型 revision、引擎版本、语言状态、处理耗时及清晰的终态。时间戳没有经过模型或对齐器验证时，返回为空或明确标记音频窗口范围，不伪造字词级时间。未启用说话人模块时不生成说话人 ID。

## 8. Mac 分发与升级

公开图形版本以 Developer ID 签名、公证和票据附加为发布门槛，并验证实际下载后的首次运行。Apple 公证是软件分发检查，不等于 App Store 审核。[S5](SOURCES.md#s5-apple-mac-软件分发)

首期更新可采用用户主动下载安装新版，先完成保留数据、兼容检查和可回退，不强制引入后台自动更新。没有证书时可以开展开发者构建测试，但不能把它标注为面向普通用户的正式安装体验；不要求用户关闭 Gatekeeper 或系统保护。
