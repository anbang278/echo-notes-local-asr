# 研发计划

状态：计划已编写，应用研发尚未开始。更新时间：2026-10-16。

## 1. 交付目标

首个可对外试用版本的目标，不是“能调用模型”，而是：普通用户在经过支持矩阵验证的 Apple Silicon Mac 上，不使用终端，不预装 Python、Homebrew 或模型，安装独立应用后可以完成模型下载、Echo Notes 配对和离线录音转写。

在独立应用链路完成前，不以设置页新增按钮或扩大模型列表作为主要进度。所有阶段完成条件均需附测试证据；以下版本名是规划标签，不代表已发布。

## 2. 范围与默认决策

| 维度 | 本轮决策 |
|---|---|
| 平台 | Apple Silicon Mac 优先；Intel Mac、Windows、Linux、移动端延后 |
| 默认模型 | Qwen3-ASR-0.6B-8bit，固定 revision；1.7B 延后 |
| 主要流程 | 文件录音转写；不做实时转写和主动麦克风采集 |
| 应用形态 | 原生控制台／菜单栏 + 隔离本地服务 |
| 分发方式 | 目标为独立签名、公证的 Mac 应用；模型数据按需下载 |
| 部署策略 | 运行时随软件交付，不在用户机器执行 pip 或安装 Homebrew |
| 升级策略 | 首期支持用户主动升级和安全回退；后台自动升级延后 |
| 集成策略 | 先保持既有本地任务协议，再补配对与自动配置 |
| 迁移策略 | 原 Echo Notes 仓库只读参考；在新仓库验证后，另行授权跨仓库修改 |
| 研发依据 | 固定上游提交、锁定依赖、单独记录版本与测试证据 |

## 3. 里程碑总览

| 里程碑 | 交付物 | 通过标准 | 前置条件 |
|---|---|---|---|
| M0：基线与打包验证 | 迁移清单、技术决策、最小运行包验证记录 | 干净 Mac 可以运行不依赖系统 Python 的短录音推理；确定最低系统版本与签名路径 | 可用的 Mac 测试设备；上游代码可读 |
| M1：可移植本地核心 | 独立运行服务、配置目录、任务协议、鉴权与测试 | 路径无开发机绑定；任务可取消／取回；资源有界；未授权访问被拒绝 | M0 技术路线确认 |
| M2：Mac 安装与模型管理 | 原生向导、运行时包、模型下载器、可恢复错误处理 | 新用户不用终端完成安装、下载、校验、启动和测试音频 | M1；可分发运行时构建链 |
| M3：Echo Notes 配对集成 | 插件适配补丁、连接发现、配对和配置迁移 | 一次授权后无需复制地址；多 Vault 安全共享；原有云端及笔记流程无回归 | M1/M2；另行授权修改主插件仓库 |
| M4：可分发测试版 | 签名、公证 DMG、测试矩阵、说明与回退指南 | 干净机器首次安装、断网转写、长录音和异常恢复验收通过 | M2/M3；签名、公证条件满足 |

版本建议：M1/M2 的开发构建使用 `0.1.0-alpha.*`，M4 通过后才考虑 `0.1.0-beta.1`。是否进入稳定版取决于试用证据，不按日历自动升级状态。

## 4. M0 — 基线与最小打包可行性

规划工件已准备：[M0 任务](../.trellis/tasks/10-16-m0-baseline-packaging/prd.md) 与 [Pi 交接](../.trellis/tasks/10-16-m0-baseline-packaging/handoff.md)。状态 planning，未授权应用实施；本轮初始化不启动 M0。

### 任务

| ID | 任务 | 验收输出 |
|---|---|---|
| M0-01 | 固定现有服务与插件基线，列出迁移文件和版权信息 | `SOURCE_BASELINE` 记录 commit、文件范围、保留与改造项 |
| M0-02 | 确定首轮支持矩阵 | M2 / 16GB 基准；最低 macOS 待实测；列出待补设备而非假称已支持 |
| M0-03 | 验证自包含 Python / MLX / 音频解码运行包 | 无全局 Python、Homebrew、Xcode CLI 依赖的短录音推理证据 |
| M0-04 | 检查签名、公证、原生扩展和动态库加载 | 组件清单、签名条件、首启验证路径及阻塞记录 |
| M0-05 | 确认数据目录、模型许可与包分发责任 | 模型来源、许可证核验项、目录与迁移决策 |

### 应主动验证的风险

`.venv` 不能直接搬家、动态库查找路径错误、FFmpeg 路径固定、MLX 对系统版本的约束、原生库签名失败、模型下载源不可达。这些风险优先于完整 UI 开发。

如 Python 方案不能形成可维护、可签名的运行包，先记录具体失败证据，再对 Swift 推理做有边界的对照验证。未经证据不重写整个推理层。

**阶段退出条件：**架构路线可执行且阻塞明确；没有证书时可完成运行实验，但不能把开发构建等同于普通用户可安装版本。

## 5. M1 — 可移植本地核心

| ID | 任务 | 验收输出 |
|---|---|---|
| M1-01 | 从固定基线迁入必要服务代码与测试，保留版权 | 最小源码集；无 Vault、模型、个人日志和开发机状态 |
| M1-02 | 配置化模型目录、解码器、运行根目录 | 中文用户名、空格路径、非默认安装位置测试 |
| M1-03 | 服务、实例、客户端和任务身份管理 | 本机鉴权、任务归属、令牌撤销及拒绝未授权请求测试 |
| M1-04 | 保持任务协议和有界上传／解码行为 | 重复创建／提交、源文件变化、分块校验和大文件拒绝测试 |
| M1-05 | 完整生命周期：启动、忙碌、取消、退出、空闲卸载 | 真实计算停止与 UI 终态一致；不误杀旧服务或无关进程 |
| M1-06 | 结果持久化、过期与客户端恢复 | 保存失败可重取；实例变化可识别；无隐式重算 |

**关键约束：**保留已有协议的可恢复通信能力，不把它描述为进程崩溃后的断点续算。硬退出或睡眠后的处理必须有明确状态。普通模型不以说话人和对齐模型存在作为启动前提。

**阶段退出条件：**服务可在不同用户目录独立运行，协议与安全测试通过；M2 可以只通过受限管理接口调用它。

## 6. M2 — Mac 安装与模型管理

| ID | 任务 | 验收输出 |
|---|---|---|
| M2-01 | 首次启动向导：环境、模型、下载来源、磁盘、隐私 | 形成可评审界面；不展示不可用的推荐模型 |
| M2-02 | 随应用交付固定运行时与必要解码组件 | 应用安装不调用系统包管理器，不修改全局配置 |
| M2-03 | 模型目录与签名／内置清单，下载进度与恢复 | 相同 revision 可恢复；校验失败不可进入“已安装” |
| M2-04 | 启动、停止、内置测试、资源状态与诊断 | 区分模型缺失、服务未启动、模型加载失败和推理错误 |
| M2-05 | 卸载、修复与用户主动软件升级 | 删除粒度清晰；旧版可回退；共享缓存不误删 |

推荐页面只保留“首次设置”“运行状态”“模型管理”“诊断与高级设置”四个区域，不做通用模型市场。下载进度与模型加载进度分开显示，不能长期停在一个无法解释的百分比。

**阶段退出条件：**一名未参与研发的用户可以不用终端走完首次安装至测试音频成功。模型下载与故障恢复实测，不使用模拟进度替代真实下载链路。

## 7. M3 — Echo Notes 配对与自动配置

| ID | 任务 | 验收输出 |
|---|---|---|
| M3-01 | 连接发现、真实服务身份确认和用户配对 | 陌生监听端口不能取得凭据；单次挑战不可重放 |
| M3-02 | 插件读取能力、自动填写本地 profile | 不覆盖其他 Provider、AI 分析或 Memory 设置 |
| M3-03 | 明确“安装”和“使用本地转写”是两步 | 安装助手不自动切换正在运行的任务或用户默认 Provider |
| M3-04 | 启动策略、多 Vault 共用和实例恢复 | 关闭一个 Vault 不截断另一个任务；用户停止后不被轮询重启 |
| M3-05 | 插件回归：长录音、任务中心、Markdown 写回、诊断 | 结果保存成功后才清理；用户编辑内容和原链接保留 |

主插件当前对专有本地协议有端口和服务标识约束。自动发现新端口不能只实现助手一端；需提供旧／新客户端与旧／新服务兼容矩阵，禁止以“OpenAI 兼容”概括一切。

**授权边界：**本次初始化不修改 `anbang278/echo-notes`。M3 实施时需要针对主插件仓库单独安排授权、分支、测试和合并。

## 8. M4 — 分发、验收与试用

| ID | 任务 | 验收输出 |
|---|---|---|
| M4-01 | 完成 Developer ID 签名、公证与票据附加 | 实际构建日志、包哈希和下载后首启证据 |
| M4-02 | 干净 Mac 和升级安装矩阵 | 无开发环境首装、旧版本升级、退出重开、卸载重装 |
| M4-03 | 真实音频质量和长时处理验证 | 30 分钟与 2 小时自然录音目标样本；RTF、内存、遗漏等记录 |
| M4-04 | 安全、离线与故障注入 | 模型齐全后断网；损坏文件、下载中断、低磁盘、忙碌退出、未授权访问 |
| M4-05 | 发布说明与小范围试用 | 准确的支持范围、已知限制、反馈入口、修复与回退指南 |

完整标准见 [ACCEPTANCE](ACCEPTANCE.md)。2 小时是本轮计划的长录音验收目标，不是已验证能力；若不能通过，就缩小公开承诺并保留阻塞，不能用重复拼接压力样本替代自然录音质量验证。

**阶段退出条件：**可复查的测试版产物和证据齐全。未测的平台、低内存设备和精细说话人能力不写入“已支持”。

## 9. 后续待办，非首期承诺

待安装成功率、质量、稳定性证据形成后，再评估 1.7B 与 0.6B 取舍、可选说话人分离和强制对齐、推理分段检查点、完整自动更新、Swift 原生引擎以及 Intel Mac / Windows 支持。每项须给出新增价值、维护成本和回归矩阵，不能因上游新增支持就自动纳入产品。

## 10. 组织与执行约束

单个执行 Agent 优先按 M0 → M1 → M2 → M3 → M4 推进；确认契约后，才可以将界面、运行核心和测试并行。多人并行使用独立分支／worktree，不共享同一正在运行的 MLX 实例。

每次交付至少提供：变更文件、执行命令、真实结果、未验证内容、风险、回滚方法；同步 README 项目进度。对主服务、模型缓存、笔记和已安装应用的替换不属于“运行测试”的默认权限。
